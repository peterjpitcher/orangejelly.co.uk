## B. Components

### B1. Growth Pressure Map — built as two related designs
- **Static:** `components/diagnostic/PressureMap` — radial network (six area nodes around "the business", pressure = node size + fill: paper → peach → orange → ember) plus a `grid` variant (six tiles) for problem pages and small spaces. It is a pressure map, never a score: no totals, no /100.
- **Interactive:** `components/diagnostic/PressureCheck` — symptom buttons → map highlights connected areas → connected-causes panel → diagnostic CTA. Ships with the six blueprint symptoms.

### B2. Scorecard — built
`components/diagnostic/Scorecard`. Intro → 12 statements (2 per area, 4-point frequency scale) with progress → result = PressureMap grid + named heaviest pressure + diagnostic handover. `onComplete` fires with raw answers for your analytics. Replaces the retired ROI calculator; the result copy pattern ("a signal, not a diagnosis") is deliberate.

### B3. Next-step chain — built
`components/editorial/NextStep`. `from="article|problem|case"` sets stage defaults; max 2 links. This is the one component that carries article → problem → case → offer across all 106 posts. Wire it from your related-links data (`migrate-related-links.ts` output maps cleanly onto `{stage,title,desc,href}`).

### B4. Site search — built
`components/chrome/SiteSearch`. Input, highlighted results, and a no-results state that routes to the problems hub. Feed it your existing `search-index.json`; `onQuery` hooks a backend if you move off client-side.

### B5. Mobile navigation — built
Header upgraded in place (`components/chrome/Header`): nav items accept `sub[]`, rendered as grouped sections in the full-screen ink drawer (the 8 problem pages live under "Growth problems"; `more:true` styles the view-all row). Desktop stays a flat bar. Also new: `tone="orange"`.

### B6. Smaller gaps
- **Pagination** — `editorial/Pagination`. Use `hrefFor` (real links) on `/insights`.
- **Empty states** — `feedback/EmptyState`. Always ships an action.
- **Loading/skeleton** — `feedback/Skeleton` (`text|card|article`). Replaces `ui/skeleton`.
- **Share buttons** — `editorial/ShareRow`. The blog-article template did NOT cover this; add it under the byline.
- **Cookie notice** — `chrome/CookieNotice`. localStorage-persisted, equal-weight decline.
- **Tabs** — survives: `editorial/Tabs`, in-page content switching only, never navigation.
- **Data tables in articles** — confirmed: `.oj-prose` already styles `table/th/td` (`tokens/prose.css`). Nothing to build.
- **Taxonomy colours** — resolved: seven muted `--cat-*` token pairs in `tokens/colors.css` (demand teal `#2E7D74`, convert slate `#3E5C8A`, margin plum `#7A4468`, ops olive `#6B6D2F`, experience violet `#6C5B9E`, scale pine `#356950`, hospitality umber `#8A5A2E`, each with a `-soft` tint). Component: `editorial/CategoryTag`. A category is never orange.
- **Seasonal calendar / playbooks** — `marketing/SeasonalBand`, sector hub + hospitality pages only.

## C. Decisions — all settled

1. **Lowercase display headings: YES, site-wide.** Now enforced globally in `tokens/base.css` (`h1,h2,.oj-display{text-transform:lowercase}`), not per-template. Wrap proper nouns in `.oj-keep-case` (see Results/About: "The Anchor"). h3 and below stay sentence case. The About `textCase` toggle is gone.
2. **Orange header rule: conversion pages only.** Start Here, the growth-problem pages and the problems hub get it; every other page — including About, now reverted to cream — keeps the cream header. In code: `Header tone="orange"` on those routes, default elsewhere.
3. **Fonts: build on Schibsted Grotesk.** No licensed family is coming; treat the Google Fonts load as production. The type scale is final.
4. **Hospitality pages: full new design system.** No visually distinct treatment — the sector reads through content and the umber taxonomy hue only (see SectorHub/SectorLanding).
5. **Taxonomy colour:** see B6 above.
6. **Pricing: confirmed nothing else assumes a price slot.** We audited the system; OfferCard was the only component that referenced pricing, and its docs now state the permanent rule (bespoke work, no prices, footnote carries the investment conversation). The SectorLanding FAQ shows the approved "what does it cost" answer pattern.

## D. Out of scope — agreed
`/availability` stays out of the redesign on its current styling. If you later want it visually reconciled, it is a new request.
