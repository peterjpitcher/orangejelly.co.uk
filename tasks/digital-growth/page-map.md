# Digital growth page map and release baseline

5 September 2026. Peter authorised implementation in full after approving the revised offer and implementation plan.

## Decisions

- Homepage describes websites, applications and connected systems first; general consultancy is supporting context.
- `/solutions/hospitality-websites` owns hospitality web design and pub/restaurant variants. Hotel-only expansion is deferred because current published proof is The Anchor.
- `/solutions/bespoke-applications` owns bespoke web application development and customer portal variants. It describes browser applications, not native mobile apps.
- `/solutions/booking-systems` owns custom booking systems. Its purpose is booking rules, confirmation and integration versus replacement; the website page owns discovery and the journey into an existing booking tool.
- `/growth-problems/using-ai-intelligently` retains AI consultation intent and links to implementation pages. Existing `/tools/ai-readiness` stays in place as the assessment, not a duplicate commercial page.
- `/pub-marketing` and `/sectors/professional-services` retain their existing URLs and supporting sector purposes.
- Existing route manifest had no registration or redirect for any of the three new paths. No guide, insight or case-study URL changes.

## Search checks

UK-qualified searches on 5 September found distinct commercial page types. Sources checked:

- Hospitality websites: https://www.servdmedia.co.uk/services/hospitality-web-design and https://www.thefoundryhospitality.com/hospitality-websites-apps describe booking-oriented website builds and integrations.
- Applications: https://abcode.co.uk/applications/ and https://www.fullycoded.com/website-development/application-development/ describe business applications and internal systems.
- Booking systems: https://www.titanstudio.co.uk/services/custom-booking-systems describes bespoke booking software.
- AI: https://www.aibizassist.co.uk/ describes assessment, implementation and adoption.

These checks support distinct search intent, not a promise of ranking opportunity. They used UK-qualified web search rather than a geographically controlled Google result capture. Exact ranks, ads, AI Overviews and other result features remain unverified. No invented organic difficulty score is used.

`keyword-evidence.csv` preserves the submitted historical keyword rows and source filenames. UK segmentation is confirmed; the exports do not expose a language setting. Monthly data are empty and the 50/500/5,000 values are coarse. Paid competition is labelled separately from organic ranking difficulty. No fifth-round keyword is added to another close variant's volume.

## Existing search performance

`gsc-baseline.json` records selected page rows and date/filter metadata from both supplied Search Console archives. They contain separate query and page totals. They cannot prove which page ranks for a particular query. No supplied query evidence establishes an existing commercial keyword winner for the new pages. Absence from an export is not zero demand or zero impressions.

The new pages have no pre-launch page baseline. Record their first complete post-launch period as baseline collection, alongside unchanged guide performance and existing page totals. Review 28 complete days after launch and again after eight weeks. Future review is not automatically scheduled.

## Public evidence

`src/app/results/case-studies.ts` records The Anchor website rebuild around real searches, an improved private-hire enquiry route, and booking confirmations/reminders. Use these as the concrete website and booking examples with explicit own-venue attribution. Overall growth results are not attributed solely to a particular website, system or AI feature.

There is no separately verified public bespoke-application portfolio in these source files. Show potential application scope as examples of what can be built, not fictitious completed client projects. Do not publish private application screenshots, customer details, new integration claims or logos. The user can add approved portfolio evidence later without blocking an accurate service description.

## Enquiry measurement

Existing source cleaning preserves public landing paths, but referrers are reduced to origins and the destination form records `/start-here`. First landing is retained only where existing consent-based capture supports it. Therefore service-level attribution is incomplete and must not be presented as a complete funnel. Preserve existing consent and attribution rather than introduce an unplanned query contract. The existing authenticated summary remains useful for stored enquiries and qualification; a service breakdown is not added in this release.

No new commercial promise, schema, lead field, tracking event or live test message is included.
