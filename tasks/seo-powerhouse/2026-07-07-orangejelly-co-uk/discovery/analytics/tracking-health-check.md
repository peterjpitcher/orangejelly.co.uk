## Ticket-ready tracking fixes

### T1 — `generate_lead` on contact-form success (Tier-1, do first)
- **Problem:** Primary conversion fires no analytics event.
- **Affected:** `src/components/forms/contact-form.tsx` (onSubmit success branch); GTM container GTM-WBHJ7Q2H; GA4.
- **Event name:** `generate_lead`
- **Trigger:** contact form `submitStatus === 'success'` (client-side, after `submitContactForm` returns no error).
- **GA4 parameters:** `form_name: 'contact'`, `package` (selected package value), plus inherited source/UTM.
- **Key event:** Yes.
- **Consent dependency:** Push to dataLayer regardless (event carries no PII); GA4 tag respects Consent Mode `analytics_storage`. Do NOT gate this behind `hasAnalyticsConsent()` in a way that drops the event silently — prefer Consent Mode handling it at the tag.
- **Implementation:** add `window.dataLayer?.push({ event: 'generate_lead', form_name: 'contact', package })` in the success path; create GTM Custom Event trigger `generate_lead` → GA4 Event tag `generate_lead`; mark key event in GA4 Admin.
- **QA / acceptance:** test submission shows `generate_lead` in GA4 DebugView, increments the key event, and the lead appears in `/admin`.
- **Rollback:** remove the push / pause the GTM tag. No user-facing impact.

### T2 — Verify GA4 Config tag + SPA page_view (Tier-1, do first)
- **Problem:** GA4 tag existence and route-change page_view are unverified.
- **Affected:** GTM container GTM-WBHJ7Q2H.
- **Fix:** confirm a GA4 Configuration/Config tag with a valid `G-` ID fires on All Pages; enable page-view on browser-history changes so Next.js client navigations count.
- **Acceptance:** page_view in Realtime on first load AND on each in-app navigation (no reload).
- **Rollback:** n/a (verification + config).

### T3 — Phone, email, WhatsApp, CTA click events → GA4 key events
- **Problem:** `tel:`/`mailto:` clicks untracked; `whatsapp_click`/`package_cta_click`/`guide_cta_click` push to dataLayer but have no confirmed GA4 tags; `guide_cta_click` has no call site.
- **Affected:** GTM container; `contact/ContactPage.tsx`, `FooterSimple.tsx`, guide bridge CTA component.
- **Fix:** GTM click triggers on `a[href^="tel:"]` → `phone_click` and `a[href^="mailto:"]` → `email_click`; GTM Custom Event triggers for the three existing dataLayer events → GA4 events; instrument the guide→service bridge CTA to fire `guide_cta_click`. Mark `phone_click`, `email_click`, `whatsapp_click` as key events (all are enquiry proxies here).
- **Consent dependency:** custom dataLayer events are gated by `hasAnalyticsConsent()`; tel/mailto GTM triggers respect Consent Mode.
- **Acceptance:** each action visible in DebugView on a consented session.

### T4 — Consent store reconciliation
- **Problem:** two consent representations (`gtag` Consent Mode state and `tracking.ts`'s `oj-cookie-consent` read) may disagree, silently suppressing custom events.
- **Fix:** ensure `CookieNotice` Accept calls `updateGtagConsent(true)` AND writes the exact shape `hasAnalyticsConsent()` accepts (`{analytics:true}` or `'accepted'`).
- **Acceptance:** after Accept, a `whatsapp_click` reaches both dataLayer and the `/api/events` Supabase log.

### T5 — Lead notification to Peter (process/reliability)

- **Fix:** mount on the guide template (recommended) or on `/contact`; then add `newsletter_signup` dataLayer push + GA4 key event. If not wanted, delete the component + action to reduce maintenance weight.
